# Lab 02: Enterprise EDR Operations & Threat Emulation (LimaCharlie + Atomic Red Team)

## Why I Built This Lab
In **Lab 01**, I focused on understanding how endpoint logs travel through a SIEM data pipeline using Splunk and Sysmon. 

While a SIEM provides deep historical visibility and aggregation, security operations centers (SOCs) depend heavily on **Endpoint Detection and Response (EDR)** platforms for real-time visibility, kernel-level telemetry, and immediate containment.

For this lab, I deployed **LimaCharlie EDR** - a cross-platform SecOps cloud platform - alongside **Atomic Red Team** (by Red Canary) to test my endpoint defenses against mapped techniques from the **MITRE ATT&CK** matrix. 

My goals for this project were:
1. Understand how an EDR agent operates live on an endpoint compared to traditional log forwarders.
2. Emulate real threat actor post-exploitation tradecraft across four distinct MITRE ATT&CK tactics (Execution, Defense Evasion, Persistence, and Discovery).
3. Author production-grade **Detection and Response (D&R)** rules in LimaCharlie using structured YAML logic.
4. Investigate process ancestry graphs, parent-child PID relationships, and troubleshoot real-world detection engineering edge cases.

## Practical Troubleshooting & Engineering Hurdles

Just like setting up Splunk in Lab 01, configuring a live EDR and executing adversarial tests surfaced real engineering hurdles:
### 1. Windows Defender Locking Up VM on Atomic Library Download
* **The Problem:** 
	* When running the initial Atomic Red Team installation script, my Windows VM froze and CPU usage spiked to 100%. 
	* Windows Defender began firing continuous alerts and quarantined multiple script definitions simultaneously.
* **Root Cause:** 
	* Atomic Red Team downloads a vast library of real exploit templates, offensive PowerShell cradles, and known attack tool definitions (like Mimikatz).
	- Defender's real-time engine inspected the incoming archive and attempted to quarantine dozens of files concurrently, locking the filesystem.
* **The Fix:** 
	* In an elevated PowerShell prompt, I added a targeted folder exclusion in Defender for the staging directory before re-extracting the library:
		```powershell
		Add-MpPreference -ExclusionPath "C:\AtomicRedTeam"
		```
	- This allowed the emulation framework to extract cleanly without crashing the operating system while leaving the rest of the OS fully protected and monitored.

### 2. Session Volatility of PowerShell Modules
* **The Problem:** 
	* After successfully testing with `Invoke-AtomicTest`, closing and reopening the terminal resulted in `Invoke-AtomicTest : The term 'Invoke-AtomicTest' is not recognized`.
* **Root Cause:** 
	* Functions imported via script blocks in PowerShell reside exclusively in the volatile memory space of that active process PID.
* **The Fix:** 
	* I backed the import into the persistent PowerShell profile (`$PROFILE`) so the execution harness automatically loads whenever a new administrative shell spawns:
		```powershell
		Add-Content -Path $PROFILE -Value 'Import-Module "C:\AtomicRedTeam\invoke-atomicredteam\Invoke-AtomicRedTeam.psd1" -Force'
		```

## Key Lessons Learned

1. **EDR vs. SIEM Visibility:**
	- A SIEM relies on logs generated by Windows after the fact. 
	- The EDR monitors memory, active process handles, and kernel callbacks in real time.
	- It allows an analyst to observe cryptographic hashes, digital signature verification flags (`FILE_IS_SIGNED`), and parent/child PIDs instantly.
2. **Living-Off-The-Land Requires Behavioral Context:**
	- Binaries like `wevtutil.exe`, `schtasks.exe`, and `powershell.exe` are completely legitimate, digitally signed Microsoft files.
	- Signature-based antiviruses will rarely flag them on their own. 
	- Effective detection engineering must inspect command-line arguments, parent process lineage, and execution bursts.
